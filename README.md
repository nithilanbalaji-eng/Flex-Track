# Flex Track

**Train together. Track everything. Never skip a day.**

Flex Track is a full-stack fitness app for people who go to the gym with friends. Build workout plans
together, share them with your crew, log every session, track calories against a personalized target,
let an AI coach design your program, and pull burned calories straight from Apple Health.

---

## Features

| Feature | What it does |
| --- | --- |
| **Accounts** | Email + password signup/login, plus **Continue with Google** and **Continue with Apple**. JWT-based sessions. |
| **Shared workout plans** | Build multi-day splits with sets, reps, rest and notes. Share a plan with a specific friend by email, or attach it to a group so everyone sees it. |
| **Gym crew groups** | Create a group, get an invite code, send it to your training partners. Plans attached to a group are visible to every member. |
| **Gym log** | Check in each time you train. Streaks, 30-day counts, all-time totals, and a 6-month contribution-style heatmap. |
| **AI coach** | A 4-step questionnaire (age, weight, height, goal, experience, equipment, days/week, injuries) produces a full periodized program. Uses Claude when an API key is configured, and falls back to a built-in rule-based coaching engine so it always works. |
| **Calorie tracker** | Log food by meal with macros. Daily target and protein/carb/fat split are computed from your profile via Mifflin-St Jeor BMR → TDEE → goal adjustment. |
| **Apple Health sync** | Each user gets a personal, revocable webhook key. Point a HealthKit export shortcut at Flex Track and your workouts + active energy flow into your gym log automatically. |

**Backend** — Node.js, Express, TypeScript, Prisma ORM, SQLite (swap `DATABASE_URL` for Postgres in production),

**Frontend** — React 18, TypeScript, Vite, Tailwind CSS, React Router, Axios, date-fns.

## Getting started

You need Node.js 18+.

### 1. Backend

```bash
cd backend
npm install
cp .env.example .env          # defaults work out of the box with SQLite
npx prisma migrate dev        # creates the database and runs the seed
npm run dev                   # http://localhost:4000
```

### 2. Frontend

In a second terminal:

```bash
cd frontend
npm install
cp .env.example .env          # optional — only needed for Google/Apple sign-in
npm run dev                   # http://localhost:5173
```

Vite proxies `/api` to `http://localhost:4000`, so no CORS setup is needed for local development.

## Configuration

Everything below is optional — the app runs fully without any of it.

### Google Sign-In

1. Create an OAuth Client ID (type: Web application) in the [Google Cloud Console](https://console.cloud.google.com/apis/credentials).
2. Add `http://localhost:5173` as an authorized JavaScript origin.
3. Set the same client ID in both places:
   - `backend/.env` → `GOOGLE_CLIENT_ID`
   - `frontend/.env` → `VITE_GOOGLE_CLIENT_ID`

The backend verifies the ID token server-side with `google-auth-library` before issuing a session.

### Sign in with Apple

1. Create a Services ID and key in the [Apple Developer portal](https://developer.apple.com/sign-in-with-apple/).
2. Set `APPLE_CLIENT_ID`, `APPLE_TEAM_ID`, `APPLE_KEY_ID`, `APPLE_PRIVATE_KEY` in `backend/.env`.
3. Set `VITE_APPLE_CLIENT_ID` in `frontend/.env`.

Identity tokens are verified server-side with `apple-signin-auth`.

### AI coach

Set `ANTHROPIC_API_KEY` in `backend/.env` to have plans generated by Claude. Without a key, Flex Track uses
its built-in rule-based coaching engine — the feature works either way, and the UI tells you which one
produced the plan. `ANTHROPIC_MODEL` defaults to `claude-sonnet-5`.

### Apple Health

Apple only exposes HealthKit to native iOS apps, so a browser can't read it directly. Flex Track bridges
this with a per-user webhook:

1. Open **Settings** in the app and copy your webhook URL and personal key.
2. On your iPhone, use a HealthKit export app (e.g. *Health Auto Export*) or a Shortcuts automation, and
   add a REST/webhook destination that POSTs JSON to that URL.
3. Send a payload shaped like:

```json
{
  "healthApiKey": "your-personal-key",
  "workouts": [
    {
      "workoutType": "Traditional Strength Training",
      "startDate": "2026-01-15T18:00:00Z",
      "endDate": "2026-01-15T19:10:00Z",
      "caloriesBurned": 480
    }
  ]
}
```

Each synced workout is recorded and mirrored into your gym log, so streaks and burned-calorie totals stay
accurate. You can rotate the key from Settings at any time.

## API reference

All routes are prefixed with `/api`. Everything except signup/login/oauth and the Health webhook requires
an `Authorization: Bearer <token>` header.

**Auth**
```
POST   /auth/signup                 { name, email, password }
POST   /auth/login                  { email, password }
POST   /auth/google                 { idToken }
POST   /auth/apple                  { identityToken, fullName? }
GET    /auth/me
PUT    /auth/me                     profile fields (age, weightKg, goal, …)
POST   /auth/me/rotate-health-key
```

**Workout plans**
```
GET    /plans                       plans you own, are shared on, or via your groups
POST   /plans                       { name, days: [{ dayNumber, title, exercises[] }], groupId? }
GET    /plans/:id
PUT    /plans/:id                   owner only
DELETE /plans/:id                   owner only
POST   /plans/:id/share             { email }
DELETE /plans/:id/share/:userId
```

**Groups**
```
GET    /groups
POST   /groups                      { name }  → returns invite code
POST   /groups/join                 { inviteCode }
DELETE /groups/:groupId/leave
```

**Gym log**
```
GET    /logs
GET    /logs/summary                streaks + session counts + burned calories
POST   /logs                        { date, durationMinutes?, caloriesBurned?, notes? }
DELETE /logs/:id
```

**Calories**
```
GET    /calories?date=YYYY-MM-DD    entries + totals + computed target/macros
POST   /calories                    { date, mealType, foodName, calories, protein?, carbs?, fat? }
DELETE /calories/:id
```

**AI coach**
```
POST   /ai/generate-plan            questionnaire → generated plan
POST   /ai/save-plan                persist a generated plan
```

**Apple Health**
```
POST   /health/webhook              { healthApiKey, workouts[] }   (no bearer token — key authenticates)
GET    /health/synced
```

## Production notes

- Point `DATABASE_URL` at Postgres and change `provider` in `prisma/schema.prisma` to `postgresql`, then
  run `npx prisma migrate deploy`.
- Set a strong `JWT_SECRET` and the correct `CLIENT_URL` for CORS.
- Build with `npm run build` in each package; serve `frontend/dist` from any static host and run
  `npm start` for the API.
